# Feature Specification: rodio 替换手写 cpal 播放层

**Feature Branch**: `002-rodio-playback-migration`

**Created**: 2026-08-09

**Status**: Draft

**Input**: User description: "计划用 rodio 替换 cpal 看看可行性 我们要跨平台"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 任意平台上 TTS 都能可靠出声 (Priority: P1)

用户在 macOS、Windows、Linux x86 或嵌入式 Linux (Rockchip 开发板) 上运行
server，不管接的是板载声卡、USB 声卡还是蓝牙耳机，触发语音回复时扬声器
都能正常播放，不出现"配置不支持"类的静默失败。

**Why this priority**: 这是本次迁移的直接动机——手写播放层在只收特定位宽
的 USB 声卡 (PCM2912A) 上静默失败，排查和修复都要理解底层音频细节。语音
对话是机器人的核心交互，播放可靠性是 P1。

**Independent Test**: 在每种目标平台/声卡组合上触发一次 TTS 播放，能清晰
听到完整语音即为通过。仅实现本故事即可交付价值（修复已知无声问题并免疫
同类问题）。

**Acceptance Scenarios**:

1. **Given** server 运行在仅支持 16-bit 位宽的 USB 声卡的 Linux 设备上,
   **When** 触发 TTS 播放, **Then** 扬声器正常出声, 无配置不支持错误
2. **Given** server 运行在 macOS / Windows 上, **When** 触发 TTS 播放,
   **Then** 行为与迁移前一致, 正常出声
3. **Given** 用户切换到另一输出设备, **When** 再次触发 TTS 播放,
   **Then** 新设备正常出声, 无需重启服务

---

### User Story 2 - 更换语音模型不牵动播放代码 (Priority: P2)

用户（或开发者）把 TTS 模型换成输出采样率不同的型号（例如从 16kHz 换成
24kHz），不需要修改任何播放相关代码，也不需要关心声卡是否原生支持该
采样率，语音照常播放且音调正确。

**Why this priority**: 播放层应自动适配源格式与设备能力的差异，这是衡量
"替换是否真正到位"的关键。当前实现只处理了位宽问题，采样率不匹配仍会
失败。

**Independent Test**: 用不同采样率的合成音频触发播放，声音清晰、速度音调
正常。

**Acceptance Scenarios**:

1. **Given** TTS 模型输出 24kHz 音频而声卡不支持 24kHz, **When** 播放,
   **Then** 正常出声且语速音调正确
2. **Given** TTS 模型输出单声道而设备以立体声运行, **When** 播放,
   **Then** 正常出声

---

### User Story 3 - 播放层可维护性 (Priority: P3)

后续维护者阅读或修改播放代码时，不需要理解各平台音频后端的差异；代码中
不存在针对特定设备/平台的探测与特判分支，异常路径有明确日志。

**Why this priority**: 这是迁移的长期收益，但不直接产生用户价值，排 P3。

**Independent Test**: 代码评审确认播放路径无设备/平台特判；故障注入
（拔掉声卡）时日志能明确指示问题。

**Acceptance Scenarios**:

1. **Given** 播放设备在播放中被拔出或不可用, **When** 触发播放,
   **Then** 返回明确错误并记录可读日志, 服务不崩溃

---

### Edge Cases

- 播放中途输出设备被拔出：当前播放报错并记录日志，后续播放尝试在新
  默认设备上进行或明确报错，进程不 panic。
- 合成完成但队列已空（极短文本）：判定播放完成的逻辑不死等。
- 流式播放中合成线程报错中断：已合成的部分播完后流程正常收尾，不挂起
  调用方。
- 设备被其他进程独占：返回明确错误而不是无限等待。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 在所有目标平台 (macOS, Windows, Linux x86,
  Linux ARM 嵌入式) 上成功播放 TTS 音频, 包括仅支持特定位宽/声道/采样率
  组合的声卡
- **FR-002**: System MUST 自动适配源音频与播放设备之间的位宽、声道数、
  采样率差异, 无需调用方或用户介入
- **FR-003**: System MUST 同时支持整段播放 (合成完成后一次播放) 与流式
  播放 (边合成边播放) 两种模式, 两种模式行为一致
- **FR-004**: System MUST 提供准确的播放完成判定: 非流式阻塞到全部样本
  播完; 流式在"合成结束 + 已合成内容播完"时判定完成, 两种模式都不得
  提前截断或死等
- **FR-005**: 播放代码 MUST NOT 包含针对特定设备型号或平台的探测/特判
  分支 (如按声卡型号选择位宽)
- **FR-006**: System MUST 在播放失败时返回明确错误并记录可读日志, 进程
  不崩溃, 后续播放可重试
- **FR-007**: 切换输出设备后 MUST 用新设备正常播放, 无需重启服务
- **FR-008**: 迁移 MUST NOT 改变 ASR 录音链路的行为 (本特性范围只覆盖
  播放)

### Key Entities *(include if feature involves data)*

- **TTS 音频片段**: 合成引擎产出的单声道浮点样本序列 + 采样率, 是播放层
  的唯一输入
- **输出设备**: 用户配置或系统默认的音频输出端点, 能力 (位宽/声道/采样率)
  因平台与硬件而异

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 4 种目标平台/系统组合上 TTS 播放成功率 100% (含此前失败的
  仅 16-bit USB 声卡场景)
- **SC-002**: 更换输出采样率不同的语音模型后, 零播放代码修改即可正常
  播放 (音调语速正确)
- **SC-003**: 播放层代码中的设备/平台特判分支数量为 0
- **SC-004**: 流式与非流式播放的端到端听感不回退: 播放无提前截断、无
  可感知的额外停顿 (主观试听 + 日志耗时对比迁移前)
- **SC-005**: 迁移后播放相关代码行数较迁移前 (约 200 行手写回调/探测/
  兜底逻辑) 减少 50% 以上

## Assumptions

- 范围只覆盖 **TTS 播放**; ASR 录音链路继续使用现有实现, 不在本次迁移
  范围 (录音侧对缓冲与延迟有独立约束, 且工作正常)
- "可行性验证"以实机表现为准: 迁移后需在 macOS 与 Rockchip 设备 (接
  PCM2912A USB 声卡) 实测两条播放路径; Windows/Linux x86 以可构建 +
  代码路径一致为准
- 新依赖只允许引入播放核心能力, 不引入音频解码器等无关组件
- 现有播放层的完成判定语义 (等全部样本播完才返回) 是对外契约, 迁移后
  保持等价
